# Internationalisation et RTL — KINEDOK ACADÉMIE

Trois langues : **français** (défaut), **anglais**, **arabe** avec mise en page
droite-à-gauche complète.

## 1. Principe

Aucun texte d'interface n'est écrit dans un composant. Tout passe par :

```js
KA.i18n.t('common.actions.download');                  // « Télécharger »
KA.i18n.t('dashboard.hello', { name: 'Amine' });        // interpolation
KA.i18n.n(3, 'common.units.results');                   // pluriel : « 3 résultats »
KA.i18n.term('regions', 'genou');                       // taxonomie : « Genou »
KA.i18n.content(resource, 'title');                     // contenu traduit si dispo
```

Les dictionnaires vivent dans `src/locales/fr.ts`, `src/locales/en.ts`, `src/locales/ar.ts` et
partagent **exactement** la même arborescence de clés :

```text
common      marque, navigation, actions, libellés, unités, tri, états,
            pagination, toasts, avertissement médical, pied de page, compte
taxonomies  types de ressources, types d'outils, niveaux, régions,
            spécialités, langues, formats, difficulté, types de leçon,
            statuts, rôles, objectifs d'exercice
home        héros, statistiques, cartes de sections, sections, étapes, écosystème
auth        connexion, inscription, mot de passe oublié, erreurs
library · courses · webinars · tools · pathologies · exercises · search
dashboard · profile · admin · legal
```

Chaque namespace de premier niveau correspond au fichier JSON attendu par
next-intl lors de la migration : `common` → `locales/fr/common.json`, etc.

### Contrôle automatique de complétude

`KA.i18n.t()` journalise `[i18n] clé manquante : …` dans la console lorsqu'une
clé est absente et retombe sur le français. Pour vérifier l'ensemble du site :

```js
// À coller dans la console du navigateur
(function () {
  var routes = ['', 'bibliotheque', 'formations', 'webinaires', 'outils',
                'pathologies', 'exercices', 'recherche', 'dashboard', 'profil',
                'parametres', 'faq'];
  var missing = [];
  var warn = console.warn;
  console.warn = function () { missing.push([].join.call(arguments, ' ')); };
  ['fr', 'en', 'ar'].forEach(function (loc) {
    routes.forEach(function (p) { KA.router.navigate(p, { replace: true, locale: loc }); });
  });
  console.warn = warn;
  return missing.filter(function (v, i, a) { return a.indexOf(v) === i; });
})();
```

Résultat attendu : `[]` — c'est l'état actuel des trois dictionnaires.

## 2. Ajouter une clé

1. Ajoutez-la dans `src/locales/fr.ts` (référence).
2. Reportez-la dans `en.ts` et `ar.ts`, **au même endroit**.
3. Utilisez `KA.i18n.t('namespace.chemin.cle')` dans le composant.

## 3. Ajouter une langue

1. Créez `src/locales/xx.ts` sur le modèle de `fr.ts`.
2. Déclarez la locale dans `src/i18n/core.ts` (l'import du dictionnaire suffit :
   aucune balise `<script>` à ajouter, Vite s'occupe du bundle) :

   ```js
   var AVAILABLE = [
     { code: 'fr', label: 'FR', name: 'Français', dir: 'ltr' },
     { code: 'en', label: 'EN', name: 'English',  dir: 'ltr' },
     { code: 'ar', label: 'ع',  name: 'العربية',  dir: 'rtl' },
     { code: 'xx', label: 'XX', name: '…',        dir: 'ltr' }
   ];
   ```

3. Ajoutez la balise de formatage dans `src/lib/format.ts` (`LOCALE_TAGS`).

Aucune autre modification n'est nécessaire : le sélecteur de langue, les URL
préfixées et le sens de lecture s'adaptent.

## 4. Contenus vs interface

L'interface est intégralement traduite. Les **contenus scientifiques** conservent
leur titre d'origine (usage courant en publication) et acceptent une traduction
optionnelle :

```js
{
  title: 'Reconstruction du LCA : rééducation et retour au sport par critères',
  i18n: {
    en: { title: 'ACL reconstruction: criteria-based rehabilitation and return to sport' },
    ar: { name: 'إعادة بناء الرباط الصليبي الأمامي' }
  }
}
```

`KA.i18n.content(item, 'title')` renvoie la traduction si elle existe, sinon le
titre d'origine. En base, c'est le rôle de la table `Translation`
(cf. [`DATABASE.md`](DATABASE.md)).

## 5. RTL — ce qui a été fait

Le basculement en arabe applique `<html lang="ar" dir="rtl">` et **toute** la mise
en page suit, parce que le CSS n'emploie que des propriétés logiques :

| À ne pas utiliser | À utiliser |
| --- | --- |
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` |
| `padding-left` / `padding-right` | `padding-inline-start` / `padding-inline-end` |
| `left` / `right` | `inset-inline-start` / `inset-inline-end` |
| `text-align: left` | `text-align: start` |
| `border-left` | `border-inline-start` |

`src/styles/rtl.css` ne traite que les cas qu'une propriété logique ne peut pas
exprimer :

- **icônes directionnelles** — seules les icônes portant la classe `.icon-flip`
  (flèches, chevrons « suivant ») sont retournées ; une loupe, un cœur ou une
  horloge ne doivent jamais l'être ;
- **dégradés** — héros, vignettes de cartes et panneau d'authentification voient
  leur origine inversée ;
- **chiffres, durées, tailles, dates** — isolés en LTR (`.ltr-nums`, `time`,
  `.file-size`, `code`) pour éviter qu'un « 2026-08 » ne s'affiche à l'envers ;
- **barres de progression** — conservent le sens gauche → droite : c'est une
  métaphore temporelle, pas du texte ;
- **interligne** — légèrement augmenté, l'arabe portant des diacritiques hautes.

### Vérifications effectuées

- Toutes les pages en `ar` : navigation, filtres, cartes, tableaux, formulaires,
  modales, tiroir mobile, tableau de bord et administration.
- Absence de défilement horizontal en 375 / 768 / 1024 / 1360 / 1600 px, en FR et
  en AR.
- Recherche arabe fonctionnelle : « الركبة » (genou) renvoie 13 résultats via les
  alias de pathologies, la normalisation supprimant les diacritiques (tashkil).

## 6. URL et référencement

Le préfixe de langue est en tête de chemin : `/fr/…`, `/en/…`, `/ar/…`. Les
segments restent en français (`bibliotheque`, `formations`, `outils`) pour garder
des URL stables et partageables, conformément à la liste de routes du cahier des
charges.

`KA.seo.set()` met à jour titre, méta-description, Open Graph, URL canonique
(`https://academie.kinedokdz.com/{locale}/{chemin}`) et données structurées
schema.org (`Course`, `Event`, `ScholarlyArticle`, `MedicalCondition`,
`EducationalOrganization`).

Lors de la migration Next.js, ajouter les balises `hreflang` :

```tsx
alternates: {
  canonical: `/${locale}/${path}`,
  languages: { fr: `/fr/${path}`, en: `/en/${path}`, ar: `/ar/${path}` }
}
```

## 7. Migration vers next-intl

1. Convertir chaque namespace en JSON :
   `src/locales/fr.ts → locales/fr/common.json`, `auth.json`, `library.json`…
   (les objets sont déjà exactement au bon format).
2. `middleware.ts` avec `createMiddleware({ locales: ['fr','en','ar'], defaultLocale: 'fr' })`.
3. Dans `app/[locale]/layout.tsx` :

   ```tsx
   const dir = locale === 'ar' ? 'rtl' : 'ltr';
   return <html lang={locale} dir={dir}>…</html>;
   ```

4. Remplacer `KA.i18n.t` par `useTranslations('namespace')` — les chemins de clés
   sont inchangés.
